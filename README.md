# 직무 공고 자동 알림

점핏 · 원티드 · 랠릿 · 잡코리아에서 새 채용공고를 30분마다 확인해서,
**내가 정한 조건에 맞는 공고만** 디스코드로 보내주는 시스템입니다.

한 번 올려두면 GitHub Actions가 클라우드에서 알아서 돌기 때문에, 내 PC가 꺼져 있어도 알림이 옵니다.

```
점핏 ─┐
원티드 ─┼─→ 공통 형식으로 변환 → 조건 필터 → 이미 보낸 것 제외 → 디스코드 카드 전송
랠릿 ─┤
잡코리아 ─┘
```

## 2. 디스코드 웹훅 만들기

웹훅은 "이 채널에 메시지를 넣을 수 있는 전용 주소"입니다. 봇을 따로 만들 필요가 없습니다.

1. 디스코드에서 알림을 받을 **서버**를 엽니다. (없으면 왼쪽 `+` 버튼으로 새 서버를 만드세요)
2. 알림 받을 채널을 하나 만듭니다. 예: `#채용공고`
3. 그 채널 이름 위에 마우스를 올리고 **톱니바퀴(채널 편집)** 를 누릅니다.
4. 왼쪽 메뉴에서 **연동 (Integrations)** → **웹후크** → **새 웹후크** 를 누릅니다.
5. **웹후크 URL 복사** 를 누릅니다.

복사한 주소는 이렇게 생겼습니다:

```
https://discord.com/api/webhooks/1234567890/AbCdEf...
```

> **이 주소는 비밀번호와 같습니다.** 아는 사람은 누구나 그 채널에 글을 쓸 수 있습니다.
> 채팅이나 공개된 곳에 붙여넣지 마세요. 아래 안내대로 `.env` 파일과 GitHub Secrets에만 넣습니다.

## 3. 내 PC에서 먼저 확인해보기

GitHub에 올리기 전에, 내 조건으로 어떤 공고가 걸리는지 눈으로 확인하는 단계입니다.

### 3-1. 설치

프로젝트 폴더에서 **`setup.bat` 을 더블클릭**합니다.
(가상환경을 만들고 필요한 패키지를 설치합니다. 1~2분 걸립니다.)

### 3-2. 미리보기

**`preview.bat` 을 더블클릭**합니다. 디스코드로 아무것도 보내지 않고, 조건에 맞는 공고만 화면에 보여줍니다.

```
=== 백엔드 신입 — 조건에 맞는 공고 11건 ===
  [원티드] 트리플오스 | 백엔드 개발자(신입)
      경력=신입~1년  지역=경기 성남시  https://www.wanted.co.kr/wd/356275
  [잡코리아] ㈜안랩 | [안랩] 2026년 연구소 상시채용
      경력=신입  지역=경기 성남시  https://www.jobkorea.co.kr/Recruit/GI_Read/49074852
  ...
```

여기서 **원하지 않는 공고가 섞여 있으면 `config.yaml`을 고치고 다시 `preview.bat`** 을 돌리세요.
[5번 항목](#5--직무경력-바꾸는-법)에 고치는 방법이 나와 있습니다.

### 3-3. 디스코드로 실제 전송 테스트 (선택)

1. 폴더 안의 `.env.example` 파일을 복사해서 이름을 **`.env`** 로 바꿉니다.
2. 메모장으로 열어 웹훅 주소를 붙여넣고 저장합니다.
   ```
   DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/1234567890/AbCdEf...
   ```
3. **`run.bat` 을 더블클릭**합니다.

디스코드 채널에 카드가 오면 성공입니다.

> 첫 실행에서는 기존 공고 수백 건이 전부 "새 공고"이므로, 도배를 막기 위해 **최신 10건만** 보내고
> 나머지는 조용히 "이미 본 것"으로 처리합니다. 이 숫자는 `config.yaml`의 `first_run_limit`입니다.

## 4. GitHub에 올려서 자동화하기

### 4-1. Git에 내 정보 등록 (처음 한 번만)

명령 프롬프트를 열고 아래를 실행합니다. 이름과 이메일은 본인 것으로 바꾸세요.

```bash
git config --global user.name "조보강"
```

```bash
git config --global user.email "bogang12345@gmail.com"
```

### 4-2. GitHub에서 빈 저장소 만들기

1. https://github.com/new 로 갑니다.
2. **Repository name**: `job-alert` (원하는 이름 아무거나)
3. **Public** 을 선택합니다.
   > Public이면 Actions 실행 시간이 무제한이라 30분 주기로 돌릴 수 있습니다.
   > 공개되는 것은 코드와 `config.yaml`(내 검색 키워드)뿐이고, **웹훅 주소는 공개되지 않습니다.**
4. 아래 "Add a README file" 등은 **모두 체크 해제**합니다. (이미 파일이 있으므로)
5. **Create repository** 를 누릅니다.

### 4-3. 올리기

만들어진 저장소 페이지에 주소가 나옵니다 (`https://github.com/내아이디/job-alert.git`).
프로젝트 폴더에서 명령 프롬프트를 열고 (주소 표시줄에 `cmd` 입력 후 엔터) 아래를 순서대로 실행합니다.

```bash
git add .
```

```bash
git commit -m "직무 공고 자동 알림 시스템"
```

```bash
git branch -M main
```

아래 줄의 주소는 **본인 저장소 주소로 바꿔서** 실행하세요.

```bash
git remote add origin https://github.com/내아이디/job-alert.git
```

```bash
git push -u origin main
```

> 로그인 창이 뜨면 GitHub 계정으로 로그인하면 됩니다.
> `.env` 파일은 `.gitignore`에 들어 있어서 **올라가지 않습니다.** 정상입니다.

### 4-4. 웹훅 주소를 Secret으로 등록

1. 내 저장소 페이지 → 위쪽 **Settings** 탭
2. 왼쪽 메뉴 **Secrets and variables** → **Actions**
3. **New repository secret** 버튼
4. **Name**: `DISCORD_WEBHOOK_URL` (오타 없이 정확히)
5. **Secret**: 복사해둔 웹훅 주소 붙여넣기
6. **Add secret**

### 4-5. 첫 실행 확인

1. 저장소의 **Actions** 탭으로 갑니다.
2. 워크플로를 실행할지 묻는 안내가 나오면 **I understand my workflows, go ahead and enable them** 을 누릅니다.
3. 왼쪽에서 **직무 공고 알림** 을 고르고, 오른쪽 **Run workflow** → **Run workflow** 를 눌러 즉시 실행합니다.
4. 1~2분 뒤 초록색 체크가 뜨고, 디스코드에 알림이 오면 끝입니다.

이제부터는 **30분마다 자동으로** 돕니다.

## 5. ★ 직무·경력 바꾸는 법

`config.yaml` 파일 하나만 고치면 됩니다. 메모장으로 열어도 됩니다.

고친 뒤에는 `preview.bat` 으로 결과를 확인하고, GitHub에 반영하려면:

```bash
git add config.yaml
```

```bash
git commit -m "필터 변경"
```

```bash
git push
```

### 경력 조건 바꾸기

```yaml
    career:
      min_years: 0
      max_years: 0        # ← 이 숫자만 바꾸면 됩니다
```

| 하고 싶은 것 | 값 |
|---|---|
| 신입만 | `min_years: 0`, `max_years: 0` |
| 3년차까지 (신입 포함) | `min_years: 0`, `max_years: 3` |
| 3~7년 경력만 | `min_years: 3`, `max_years: 7` |
| 경력 상관없이 전부 | `min_years: 0`, `max_years: 99` |

공고가 요구하는 경력 구간과 내가 정한 구간이 **겹치기만 하면** 알림이 옵니다.
예를 들어 `max_years: 3`이면 "1~5년" 공고도 옵니다 (1~3년이 겹치므로).

`include_irrelevant: true`는 "경력무관" 공고를 받겠다는 뜻입니다. 너무 많으면 `false`로 바꾸세요.

### 직무 바꾸기

`keywords.any` 목록을 통째로 바꾸면 됩니다. **하나라도 걸리면** 통과입니다.

프론트엔드로 바꾸는 예:

```yaml
    keywords:
      any:
        - "프론트엔드"
        - "frontend"
        - "React"
        - "Vue"
        - "Next.js"
      all: []
      none:
        - "인턴"
        - "백엔드"       # 백엔드 공고는 빼고 싶다면
```

- `any`: 이 중 **하나라도** 있으면 통과 (비워두면 키워드 조건 없음)
- `all`: 여기 적은 조건을 **전부** 만족해야 통과
- `none`: 하나라도 있으면 **무조건 제외**

`all`의 각 줄은 목록으로 적을 수 있고, **목록 안에서는 하나만 걸리면 됩니다.**
"직무는 백엔드 계열이면서, 언어는 Java 또는 Kotlin" 같은 조건을 이렇게 씁니다.

```yaml
    all:
      - ["백엔드", "서버", "웹 개발"]   # 이 중 하나는 반드시
      - ["Java", "Kotlin"]              # 그리고 이 중에도 하나는 반드시
```

> **같은 단어를 두 줄에 겹쳐 넣지 마세요.** 위에서 첫 줄에 `Java`를 넣으면
> 두 번째 줄과 겹쳐서 직무 조건이 사실상 사라지고, 안드로이드·프론트엔드 공고까지
> 통과합니다. 실제로 겪은 문제입니다.

**단어는 영문·숫자 경계로 매칭됩니다.** `Java`는 `JavaScript`에 걸리지 않고,
`Spring`은 `Spring Boot`에 걸립니다. 한글은 경계 없이 매칭되므로
`백엔드`는 `백엔드개발자`에 걸립니다.

**너무 짧은 한글 단어는 피하세요.** `개발`, `엔지니어`, `서버`를 넣었더니
"복합**개발** 현장 총노무", "사운드**엔지니어**(음악단)", "골프클럽 홀**서버**" 가
걸려 들어왔습니다. `개발자`, `시스템엔지니어`, `서버 개발`처럼 복합어로 적으세요.

> **`any`와 `none`의 검사 범위가 다릅니다.**
> `any`/`all`은 제목 + 직무분류 + 기술스택을 모두 봅니다 (놓치지 않으려고).
> `none`은 제목 + 기술스택 + 고용형태만 봅니다 (직무분류는 안 봄).
> 잡코리아는 한 공고에 `"백엔드개발자, 프론트엔드개발자"`처럼 여러 직무를 적어두기 때문에,
> 직무분류까지 제외 검사에 넣으면 백엔드도 함께 뽑는 정상 공고가 통째로 사라집니다.

### 여러 직무를 동시에 받기

`profiles:` 아래 블록을 통째로 복사해서 붙여넣고 이름만 바꾸면 됩니다.
`config.yaml`에는 이미 `"백엔드 경력 3년까지"` 예시가 `enabled: false` 상태로 들어 있습니다.
쓰고 싶으면 `true`로만 바꾸세요.

**다른 채널로 보내고 싶다면**: 프로필의 `webhook_env`를 `DISCORD_WEBHOOK_FRONTEND` 같은 다른 이름으로 바꾸고,
GitHub Secrets에 **같은 이름으로** 그 채널의 웹훅을 하나 더 등록하면 됩니다.

### 특정 회사의 공고만 받기

`include_companies`에 회사 이름을 적으면 **그 회사들의 공고만** 통과합니다.
비워두면(`[]`) 회사를 가리지 않습니다. 이름 일부만 적어도 되고, `"국민은행"`이라고 쓰면
`"KB국민은행"`도 잡힙니다.

```yaml
    include_companies: ["국민은행", "하나은행", "카카오", "네이버"]
```

`"대기업·금융권 IT"` 프로필이 이 방식으로 동작합니다. 회사가 이미 강한 조건이라
직무는 IT 전반으로 넓혀 놨고, 언어(Java/Kotlin) 조건은 걸지 않았습니다.

> **짧은 이름은 조심하세요.** `"라인"`이라고 적으면 `"티에스라인시스템"` 같은
> 무관한 회사가 걸립니다. 실제로 겪은 일이라 `"라인게임즈"`, `"라인플러스"`로 바꿔 놨습니다.
> 영문 약자는 안전합니다 — `"KB"`는 `"KB증권"`에 걸리지만 `"KBS미디어"`에는 걸리지 않습니다.

### 지역 바꾸기

```yaml
    locations: ["서울", "경기", "인천"]   # 비우면([]) 전국
```

### 특정 사이트만 쓰기

```yaml
    sources: [jumpit, wanted, rallit]     # 잡코리아 빼기
```

### 알림 주기 바꾸기

`.github/workflows/job-alert.yml`의 `cron` 값을 바꿉니다.

| 주기 | 값 |
|---|---|
| 30분마다 (기본) | `"*/30 * * * *"` |
| 1시간마다 | `"0 * * * *"` |
| 하루 두 번 (한국시간 9시, 18시) | `"0 0,9 * * *"` |

## 6. 문제가 생겼을 때

### 디스코드에 알림이 안 와요

Actions 탭 → 최근 실행 → 로그를 확인합니다.

| 로그에 보이는 것 | 원인과 해결 |
|---|---|
| `환경변수 DISCORD_WEBHOOK_URL 가 비어 있습니다` | Secret 이름 오타. `DISCORD_WEBHOOK_URL`인지 확인 |
| `조건 일치 0건` | 필터가 너무 좁습니다. `preview.bat`으로 조정하세요 |
| `새로 보낸 알림 0건` (일치는 있음) | 정상입니다. 이미 보낸 공고라서 다시 안 보낸 것입니다 |
| `[실패] jobkorea` | 잡코리아가 클라우드 IP를 막았을 수 있습니다. 아래 참고 |

### "조건 일치"는 있는데 알림이 안 와요

이미 보낸 공고입니다. 처음부터 다시 받고 싶으면 `state/seen.json` 파일 내용을 `{}` 로 바꾸고 push 하세요.
단, 그러면 조건에 맞는 공고가 한꺼번에 다시 옵니다.

### 워크플로가 저절로 꺼졌어요

GitHub는 저장소에 60일간 활동이 없으면 예약 워크플로를 자동으로 끕니다.
이메일로 알려주며, **Actions 탭에서 버튼 한 번으로 다시 켜면** 됩니다.

### 설정 파일을 고쳤더니 오류가 나요

`config.yaml`은 **들여쓰기에 탭 문자를 쓰면 안 됩니다.** 스페이스만 사용하세요.
오류 메시지에 어느 항목이 문제인지 한국어로 나옵니다.

## 공개 저장소와 보안

이 저장소는 Public 입니다. 무엇이 공개되고 무엇이 안 되는지 정리합니다.

### 공개되지 않는 것

| 항목 | 어디에 있나 |
|---|---|
| 디스코드 웹훅 URL | GitHub Secrets (저장소가 공개여도 Secrets 는 비공개) |
| 로컬 테스트용 웹훅 | `.env` — `.gitignore` 에 있어 커밋되지 않습니다 |

코드는 웹훅 **주소**를 담지 않고 **환경변수 이름**(`DISCORD_WEBHOOK_URL`)만 가집니다.
`config.yaml` 의 `webhook_env` 도 값이 아니라 이름입니다. 워크플로는
`${{ secrets.DISCORD_WEBHOOK_URL }}` 로 주입받습니다.

### 공개되는 것

- 코드 전체
- `config.yaml` — 내 검색 키워드, 목표 회사 목록, 경력 조건
- `state/seen.json` — 알림 보낸 공고 ID와 시각
- `tests/fixtures/` — 각 사이트의 공개 응답 샘플 (로그인 없이 받은 것이라 쿠키·토큰 없음)

즉 "이 사람이 어떤 조건으로 구직 중인지"는 드러납니다. 그게 부담스러우면
**저장소를 Private 으로 바꾸는 것**이 정답입니다. 단 비공개는 Actions 무료 한도가
월 2,000분이므로, 워크플로의 `cron` 을 `"0 * * * *"`(1시간 주기)로 함께 바꾸세요.

### ⚠️ `state/seen.json` 을 `.gitignore` 에 넣지 마세요

보안 점검 도구가 이 파일을 무시 목록에 넣으라고 권하는 경우가 있는데, **넣으면 시스템이 고장 납니다.**

GitHub Actions 는 매 실행마다 저장소를 새로 내려받습니다. 이 파일이 저장소에 없으면
매번 "기록 없음" 상태로 시작해 **모든 실행이 첫 실행으로 취급**됩니다.

실제로 재현해 본 결과입니다 (공고가 그대로인 상태에서 5회 실행).

```
seen.json 을 커밋함 (지금 방식) : [10, 0, 0, 0, 0]  -> 합계 10건
seen.json 을 무시 목록에 넣음   : [10, 10, 10, 10, 10]  -> 합계 50건
```

30분 주기이므로 하루 48회 × 10건 = **같은 공고 480건이 매일 반복 전송**됩니다.
이 파일에 들어가는 건 공개된 채용공고의 ID와 시각뿐이고, 비밀값은 없습니다.

### 웹훅이 노출됐다고 생각되면

웹훅 URL 은 비밀번호와 같아서, 아는 사람은 누구나 그 채널에 글을 쓸 수 있습니다.
스크린샷·채팅 등으로 노출된 적이 있다면 재발급하세요.

1. 디스코드 → 채널 편집 → 연동 → 웹후크 → 기존 것 **삭제** → **새 웹후크** 생성
2. 새 URL 복사
3. GitHub → Settings → Secrets and variables → Actions → `DISCORD_WEBHOOK_URL` 의 **Update** 클릭 후 교체

코드 수정이나 재배포는 필요 없습니다.

## 7. 알아두면 좋은 한계

솔직하게 적어둡니다.

1. **잡코리아는 언제든 깨질 수 있습니다.**
   공식 API가 없어 검색 결과 HTML을 읽는 방식입니다. 사이트가 개편되면 파싱이 실패합니다.
   그때도 **나머지 세 사이트는 정상 동작**하며, 로그에 `[실패] jobkorea`로만 남습니다.
   또 GitHub 서버는 해외 IP라서 잡코리아가 차단할 가능성이 있습니다.
   계속 실패하면 `sources`에서 빼거나, 그 프로필만 내 PC에서 `run.bat`으로 돌리세요.

2. **점핏·원티드·랠릿도 비공식 API입니다.**
   공개 문서가 있는 API가 아니라, 사이트가 자기 화면을 그릴 때 쓰는 주소를 그대로 사용합니다.
   주소나 응답 형식이 바뀌면 해당 사이트 파일 하나(`src/sources/*.py`)만 고치면 됩니다.

3. **원티드 공고는 제목으로만 걸러집니다.**
   원티드 목록 응답은 기술스택을 숫자 ID로만 주기 때문에 스택 이름을 알 수 없습니다.
   그래서 원티드는 `any` 키워드가 제목에만 적용됩니다.

4. **랠릿의 경력은 추정값입니다.**
   랠릿은 "3년"이 아니라 `JUNIOR`, `MIDDLE` 같은 등급으로 줍니다.
   `src/sources/rallit.py`의 `LEVEL_RANGES` 표에서 연차로 바꾸고 있고, 그 표는 직접 수정할 수 있습니다.

5. **같은 공고는 프로필이 여러 개여도 한 번만 옵니다.**
   "이미 알려준 공고는 다시 알리지 않는다"를 우선했습니다.
   두 프로필이 같은 공고를 잡으면 먼저 처리된 프로필의 채널로만 갑니다.

6. **GitHub Actions 예약 실행은 정시에 오지 않습니다.**
   부하에 따라 몇 분에서 십여 분 늦을 수 있습니다. GitHub의 정상 동작입니다.
